# 潜水艦（隠密性）実装の事前調査 2026-08-10

対象: Issue #107 Phase 8.3

## 結論

Phase 8.3 は今回実装しない。沼地・APC・湿地マップ（Phase 8.1 / 8.2 / 8.4）は既存の地形・ユニット登録・輸送コマンドの拡張で完結する一方、潜水艦の「近づかないと発見できない」規則は視界の定義を変更するため、霧の情報漏洩防止を横断的に再検証する必要がある。

## 調査結果

- `src/game/fog.ts` の `visiblePositions()` は味方ユニットの通常 `vision` だけから可視座標を作り、`visibleEnemies()` はその座標にいる敵をそのまま返す。
- その結果は、移動プレビュー（`src/game/commands.ts`）、攻撃可否、CPU判断（`src/ai/rules.ts`）、盤面描画・マス情報・戦闘予測・危険域表示（`src/main.ts`、`src/game/threat.ts`）で共有されている。
- 既存の霧テストは「未索敵の敵が移動候補・攻撃候補・CPUの判断から漏れない」ことを検証している。潜水艦だけを通常視界から除外すると、同じ判定を通さない経路（選択済み敵の危険域、CPU行動ログ、リプレイ表示など）から位置や能力が露出する危険がある。

## 次フェーズの設計条件

1. `visibleEnemies()` の後段フィルタではなく、検知能力を含めた単一の「敵ユニットを観測できるか」純粋関数を定義する。
2. 通常視界・隣接検知・将来の探知ユニットをその関数に集約し、UI・CPU・コマンド・脅威表示はすべてその結果だけを使う。
3. 潜水艦が未検知の場合の移動阻止、攻撃対象、危険域、CPUログ、保存／リプレイを含む回帰テストを追加する。
4. 上記を満たすまで、潜水艦を `unitDefinitions` へ追加しない。登録だけを先行すると、表示・生産・セーブで利用可能になり、隠密性のない不完全なユニットになるためである。
