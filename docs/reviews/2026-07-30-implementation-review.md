## 実測による裏取り

### 1. 移動しただけのユニットが「未行動」のまま残る（→ #74）

`skirmish` で歩兵 `r3` を移動させた直後:

```
AFTER MOVE:          {"hasMoved":true,"hasActed":false}
UNACTED RED COUNT:   3 of 3
RE-MOVE(待機の代用):  "Unit has already moved"
```

`moveUnit`（`src/game/commands.ts:39`）は `hasMoved` だけを立て、`hasActed` は攻撃・占領・乗船・上陸でしか立たない。一方 `unactedRedUnits()`（`src/main.ts:73-75`）は `!hasActed` だけで数える。**プレイヤーには行動を終える手段（待機）が無い**ため、3 部隊すべてを動かしても未行動部隊は 3 のままで、ターン終了確認が毎ターン必ず出る。`N` キーの巡回も移動済みユニットを選び続ける。

CPU 側には待機がある（`src/ai/rules.ts:326-331` の 0 コスト自マス移動、`src/ai/rules.test.ts:312` で固定）。プレイヤーだけが同じ選択肢を持っていない。Issue #1 §2.3 の「移動 +（攻撃 or 占領）を 1 回ずつ」に対する未達項目。

### 2. 燃料 0 の地上ユニットで CPU の手番が打ち切られる（→ #75）

`skirmish` の青軍戦車 `b2` の燃料だけを 0 にし、`runCpu()` と同じ手順で 6 ターン連続して回した:

```
round 1: actions=3 ["produce","produce","move:b1"] aborted=move b2 -> Unit is out of fuel
round 2: actions=1 ["move:b1"]                     aborted=move b2 -> Unit is out of fuel
round 3〜6: 同上
```

CPU の待機は自マスへの 0 コスト移動だが、`moveUnit` はコストを見る前に燃料 0 を一律で拒否する（`src/game/commands.ts:23`）。`runCpu()` は 1 コマンドの失敗で手番全体を終える（`src/main.ts:854`）ため、**`b2` より後ろの部隊は二度と動かない**。地上ユニットは `fuelPerTurn = 0` で自然回復しないので恒久的。#61 と症状は同じで原因だけが違う。

### 3. CPU 対 CPU 完走の現在値（→ #52 / #75 の頻度評価）

全 9 シナリオ × 3 難易度を 60 ラウンドまで回した（失敗コマンドで手番終了、`runCpu()` と同じ手順）:

| 指標 | 結果 |
| --- | --- |
| `applyGameCommand` の失敗 | **27 組合せすべてで 0 件** |
| 燃料 0 に到達した地上ユニット | **0 部隊** |
| 決着した組合せ | 11 / 27（未決着の 16 組合せも手番は正常に回り続けた） |
| 所要時間 | 27 組合せ合計で約 14 秒 |

#61 修正後の水準が維持されている。項目 2 の経路は通常の対局では踏まれず（`needsSupply` が燃料 1/3 以下で補給拠点を +80 評価するため）、自軍拠点へ到達できない位置で燃料を使い切った場合に限られる。ただし一度踏むと恒久的なので Medium とした。**この良好な値を固定するテストが無い**（#52 の受け入れ条件 2 つ目）。

### 4. 実行できない操作のボタンが有効なまま（→ #76）

- 生産ボタンの無効化条件（`src/main.ts:387-394`）は「リプレイ中／自分の手番でない／その施設で作れない種別」の 3 つだけで、**所持金を見ていない**。`produceUnit` は `Insufficient funds` で拒否する（`src/game/commands.ts:185`）
- 占領ボタンの条件（`src/main.ts:402-403`）は `hasActed` を見ていない。一度占領した歩兵を選び直すと再び押せるが、`captureProperty` は `Unit has already acted` で拒否する（`src/game/commands.ts:197`）。`#mobile-capture` も同じ判定を共有

### 5. 失敗時のメッセージ（→ #77）

`dispatch()`（`src/main.ts:166`）が `result.error` をそのままステータス行に出す。`session.ts` / `maps.ts` / `campaign.ts` は日本語を返すが、`commands.ts` / `combat.ts` は英語を返すため、`Insufficient funds` / `Target is out of range` / `Unit has already acted` などが日本語 UI に混ざる。

さらに `act()`（`src/main.ts:804-811`）は移動失敗時にその理由を「敵ユニットの危険域表示を解除しました。」で上書きし、**選択も解除する**。自軍ユニットを選んだまま移動範囲外をタップすると、無関係な文言とともに選択がやり直しになる。未索敵の敵マスをタップした場合（`src/main.ts:791`）だけは日本語の理由が出て選択も維持されるため、同じ「移動できないマスのタップ」で挙動が二通りある。

## 総評

Issue #1 のコンセプト（生産 → 移動 → 攻撃 → 占領のサイクル）は成立しており、Phase 1–4 と #14 / #20 の拡張まで実装されている。ゲームロジックは UI から分離され、コマンド経由の状態遷移でリプレイ・undo・セーブ検証が一貫して実現されている。前回レビューの High 指摘（#61 / #62 / #63）はいずれも解消され、CPU 対 CPU の完走で不正コマンドが 0 件になったことも確認した。

残る中心的な欠落は**プレイヤー側の「待機」**（#74）で、これは Issue #1 §2.3 のターンフローに対する未達であると同時に、未行動部隊カウンタ・巡回・ターン終了確認という UI 機能を一括で無意味にしている。CPU 側の同じ欠落（#75）も根が同一で、片方の修正で両方を解消できる。

品質基盤としては、`src/main.ts`（879 行、`src/` の約 15%）が依然として無検査で、本レビューの新規指摘 4 件のうち 3 件（#74 / #76 / #77）がこの範囲に集中している。#52 の jsdom 基盤の優先度は相対的に上がっている。
