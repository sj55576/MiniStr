## 実測による裏取り

### 1. 未索敵の敵が自軍生産施設に居ると、CPU が毎ターン不正コマンドを出して手番を放棄する（→ #84）

`emptyOwnedFacility`（`src/ai/rules.ts:118-128`）は `knownUnitAt` で占有を判定するため、**視認できていない敵ユニットが乗っている自軍工場を「空き」と誤認**する。最小再現（9x1 盤・青の工場 (8,0) に赤歩兵、青の戦車は (3,0) で視界外）:

```
ACTION: {"type":"produce","factory":{"x":8,"y":0},"kind":"infantry"}
RESULT: {"ok":false,"error":"Production facility is occupied"}
```

`runCpu()` の失敗時フォールバック（`src/main.ts:937-944`）は `unitId` を持つコマンドしか `wait` に読み替えられず、`produce` には `unitId` が無いため **その場で `finishCpuTurn()` に落ちて CPU の手番全体が終わる**。占領には 2 手番かかるので、敵歩兵が自軍工場に乗っている間ずっと再発する。

全 9 シナリオ × 3 難易度を 60 ラウンドまで回した実測（`runCpu()` と同じ手順）:

| 組合せ | `applyGameCommand` 失敗 |
| --- | ---: |
| skirmish / easy | 28 件（turn 33 以降、毎ターン） |
| outpost / easy | 6 件 |
| siege / easy | 1 件 |
| 上記以外の 24 組合せ | 0 件 |

失敗はすべて `produce` の `Production facility is occupied`。2026-07-30 レビュー時点の「27 組合せすべてで 0 件」から**退行している**。人間が青の生産施設へ 1 部隊置くだけで CPU を機能停止させられるため、難易度設定が無意味になる。

### 2. 9 マップ中 5 マップで航空ユニットを一切生産できない（→ #85）

#82 で生産施設を陸/空/海に分割し、組み込みシナリオは `facility-v2`（工場では航空機を作れない）になった。しかし空港は `addBuiltInAirports`（`src/game/maps.ts:246-276`）が**開始時に航空ユニットを持つ陣営にだけ**追加する。実測した生産可能ユニット:

| シナリオ | 空港 (自/敵/中立) | 赤が生産可能な航空機 | 青が生産可能な航空機 |
| --- | --- | --- | --- |
| `skirmish` | 0/0/0 | なし | なし |
| `landing` | 0/0/0 | なし | なし |
| `river` | 0/0/0 | なし | なし |
| `industrial` | 0/0/0 | なし | なし |
| `outpost` | 0/0/0 | なし | なし |
| `tundra` | 0/1/0 | **なし** | 戦闘機・爆撃機 |
| `islands` / `canyon` / `siege` | 1/1/0 | あり | あり |

#82 以前は工場で航空機を生産できたため、これらのマップは**航空戦力という選択肢そのものを失った**。生産パネルには戦闘機・爆撃機のボタンが「生産可能な空き施設がありません」で常時無効のまま並ぶ。`tundra` は防衛側（プレイヤー＝赤）だけが航空機を作れない非対称が増えている。

### 3. 自軍の空き生産施設マスへユニットを移動できない（→ #86）

`act()`（`src/main.ts:884-887`）の分岐順序は次のとおり:

```
… else if (facility && (!selected || selectedUnitIsRed())) { selectedFacility = position; }
   else if (moveSelectedUnit(position)) { … }
```

自軍ユニットを選択した状態で**自軍の空いている工場・空港・港湾**をタップすると、常に「生産先の指定」として消費され、移動コマンドが発行されない。盤面ではそのマスが「移動可能」としてハイライトされているのに移動できない。キーボード（Enter/Space）も同じ `act()` を通るため回避手段が無く、README が説明する「自軍拠点上での燃料・弾薬全回復と HP+20」を**自軍の生産施設では受けられない**。損傷部隊を工場へ下げる、空港を守るために部隊を置く、といった基本操作ができない。

### 4. 先手（赤＝プレイヤー）が恒久的に 1 収入分不利（→ #87）

`endTurn`（`src/game/commands.ts:367-372`）は手番を受け取る側にだけ収入を与える。初期状態は `activePlayer: 'red'` なので、**赤は第 1 ターンを収入なしで開始し、青は自分の第 1 ターン前に 1 回収入を得る**。`skirmish`（拠点各 4）の実測:

```
turn=1 active=red   redGold=6000  blueGold=6000
turn=1 active=blue  redGold=6000  blueGold=10000
turn=2 active=red   redGold=10000 blueGold=10000
turn=2 active=blue  redGold=10000 blueGold=14000
```

赤が自分の手番で使える資金は、青が自分の手番で使える資金より常に 4,000G 少ない。差は縮まらない。README は `skirmish` ほか 6 マップを「180 度回転対称で、両陣営の条件が揃っています」と説明しているが、資金条件は揃っていない。CPU 対 CPU で決着した対称マップ（`outpost` ×3、`industrial` ×3、`siege`/easy）は**すべて青が勝利**しており、この非対称と整合する。

### 5. エディタ/カスタムシナリオが常に `legacy-factory-air` になる（→ #88）

`createScenarioEditor()`（`src/game/editor.ts:18-28`）が生成する `ScenarioData` に `productionRules` が無く、`loadScenarioDefinitions` はオプション未指定時に `legacy-factory-air` を選ぶ（`src/game/maps.ts:101`）。エディタ UI にも生産ルールの選択肢が無い。結果として:

- エディタで作ったシナリオは**工場で航空機を生産できる**（組み込みシナリオと挙動が違う）
- `docs/production-and-merge.md:13` の「Newly saved custom scenarios persist the selected rule explicitly」は、選択肢が存在しないため実質「常に legacy が保存される」
- マス情報パネル（`src/ui/tileInspector.ts:43` の `productionKindsByTerrain`）と生産ボタンの施設名（`src/main.ts:439`）は**シナリオの生産ルールを見ず既定値（facility-v2）で表示**するため、legacy シナリオでは「空港で生産」と表示されたユニットが工場から出る

### 6. ドキュメントが #82 の変更に追随していない（→ #89）

- 地形一覧（README 173-184 行）に `airport`（空港）が無く 9 種のまま。実装は 10 種
- 「工場 … 陸上／航空部隊を生産」（README 181 行）は `facility-v2` では誤り
- マップ一覧の「生産施設は工場と港湾の合計数」（README 153-166 行）が空港を数えていない（例: `islands` は実際 12、表は 10）
- 操作方法 6.（README 33 行）が「工場または港湾」のままで空港に触れていない
- #82 で追加した**待機（行動終了）と合流の説明が README に無い**

### 7. 組み込みマップの回転対称の主張と実データの不一致（→ #90）

README 167 行は `skirmish` / `islands` / `landing` / `river` / `industrial` / `outpost` を 180 度回転対称としているが、実測では:

| マップ | 地形の不一致 | 初期ユニットの不一致 |
| --- | ---: | ---: |
| `skirmish` | 2 | 0 |
| `landing` | 0 | 4 |
| `islands` / `river` / `industrial` / `outpost` | 0 | 0 |

- `skirmish`: (5,3) が山岳、その回転先 (4,4) は森林。防御★4 と★2 が入れ替わっている
- `landing`: 青の初期配置が 1 行下にずれている（赤 歩兵 (2,2)/輸送艦 (3,2) の回転先は (7,3)/(6,3) だが、実際は (7,4)/(6,4)）。赤の輸送艦は中立港湾 (4,2) に 1 マス、青は (5,3) に 2 マスで、中継点への距離が異なる
- `canyon` は README で対称と主張していないが、自動追加された空港が赤 (2,0)・青 (8,8) と非対称（(2,0) の回転先は (9,9)）

### 8. 軽微な表示の不具合（→ #91）

- キャンペーン画面の説明が「4つの戦場を勝ち抜き」（`src/main.ts:527`）だが、`campaignStages` は 6 ステージ（`src/game/campaign.ts:11-18`）
- `unitTokens`（`src/ui/labels.ts:17-20`）で戦車と戦闘機がどちらも「戦」。同じ陣営色で盤面に並ぶと記号だけでは区別できない

## 総評

「生産 → 移動 → 攻撃 → 占領」のコアループ、地形・霧・補給・資金、シナリオ/キャンペーン/リプレイ/エディタは動作しており、純粋関数層のテスト 213 件と型チェック・ビルドはすべて通る。一方で **#82 の生産施設分割が、組み込みマップのデータ（空港の欠落）・UI の操作導線（生産先指定が移動を奪う）・エディタの既定ルール・ドキュメントの 4 か所で追随できていない**。加えて CPU の不正コマンドが再発しており、これは #52 が指摘し続けている「CPU 対 CPU 完走テストが無い」という穴からそのまま落ちたものである。
