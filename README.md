# MiniStr

ブラウザで遊べるターン制戦略ゲームです。Issue #1 の **Phase 2–6** を実装しています。

🎮 **[GitHub Pages でプレイする](https://sj55576.github.io/MiniStr/)** | 📚 [実装仕様](#実装仕様) | 🛠️ [セットアップ](#セットアップ)

## 概要

MiniStr は、地形・視界・補給・資金を考慮して部隊を運用するターン制戦略ゲームです。シナリオごとに設定された作戦目標を達成して勝利を目指します。通常戦のほか、連続するキャンペーン、リプレイ、セーブ／ロード、ブラウザ内マップエディタを利用できます。

### 主な特徴

- **戦術システム**：地形、霧、燃料、弾薬、HP、移動コスト、攻撃前の戦闘予測
- **経済と拠点**：都市・工場・港湾・司令部を占領し、収入と生産拠点を確保
- **海上輸送**：港湾で輸送艦を生産し、歩兵を乗船・上陸させて島しょ部を攻略
- **CPU 対戦**：易しい／普通／難しいの3段階。視認済み情報だけを用いて行動
- **データ駆動シナリオ**：複数マップ、作戦ブリーフィング、ターン制限、5種類の勝敗条件
- **プレイ継続機能**：手動セーブ、CPU 行動後のオートセーブ、1手戻す、リプレイの再生・JSON入出力
- **ミニキャンペーン**：4ステージを順番に解放し、S/A/B/C 評価を記録
- **マップエディタ**：地形・所有者・初期ユニット・勝敗条件を編集し、JSONで検証／入出力

## 操作方法

### 基本操作

1. **シナリオと難易度を選択**し、作戦ブリーフィングから開始します。
2. **ユニットを選択**：自軍ユニットをクリックします。
3. **移動**：選択後、移動可能なマスをクリックします。
4. **攻撃**：選択後、視認できる敵ユニットをクリックします。サイドパネルに与ダメージと反撃の予測が表示されます。
5. **占領**：歩兵を中立または敵の都市・工場・港湾・司令部へ移動し、表示される「占領」操作を実行します。占領中にそのマスを離れると、途中経過は回復します。
6. **生産**：自軍の空いている工場または港湾があるとき、ユニット生産を実行できます。

### 港湾・輸送艦

- 港湾では駆逐艦と輸送艦を生産できます。
- 歩兵は、沿岸の隣接する空の自軍輸送艦へ乗船できます。乗船したターンは輸送艦も行動済みになります。
- 輸送艦は、搭載した歩兵1部隊を隣接する空の陸地へ上陸させられます。

### キーボード操作

- **矢印キー**：盤面上のフォーカスを移動
- **Home / End**：現在の行の左端／右端へ移動
- **Enter / Space**：フォーカス中のマスを選択または行動
- **Esc**：ユニット選択を解除

### セーブ・リプレイ・キャンペーン・エディタ

- **セーブ**：手動セーブ、保存済みゲームの再開・削除、CPU行動後のオートセーブに対応します。セーブデータはブラウザのローカルストレージに保存されます。
- **1手戻す**：自軍（赤軍）の直前の操作を戻せます。CPU行動後やターン終了後は戻せません。
- **リプレイ**：対局終了後のコマンド履歴を再生できます。再生／一時停止、1手送り、再生速度変更、JSONの書き出し・取り込みに対応します。
- **キャンペーン**：キャンペーン画面から解放済みステージを選択します。勝利時は残存戦力・損失・所要ターンをもとに S/A/B/C 評価を記録し、次のステージを解放します。
- **マップエディタ**：ゲーム画面の「マップエディタ」から地形、拠点の所有者、初期ユニット、勝敗条件を編集できます。作成したシナリオはJSONで検証、書き出し、取り込みができます。

### ターンシステム

- 赤軍と青軍が交互に行動します。「ターン終了」で手番を渡し、青軍はCPUが自動操作します。
- 表示されるターン数は**両軍が1回ずつ行動した完全ラウンド数**です。青軍から赤軍へ手番が戻ると1増えます。
- 手番を受け取った陣営は、所有する拠点の数 × 1000 の収入を得ます。
- 自軍所有の拠点上にいるユニットは、手番開始時に燃料・弾薬が全回復し、HPが20回復します（最大100）。
- 燃料、弾薬、行動済み状態により、そのターンに可能な移動・攻撃が制限されます。

### 勝敗条件

シナリオは勝利条件・敗北条件・必要に応じてターン制限を持ちます。実装済みの条件は次の5種類です。

| 条件 | 内容 |
| --- | --- |
| 敵全滅 | 敵の盤上部隊をすべて撃破する |
| 敵司令部の占領 | 敵軍が開始時に所有する司令部を占領する |
| 指定地点の保持 | 指定マスを必要ターン数、連続して保持する |
| 生存 | 指定ターンまで生存する |
| スコア | 敵部隊の撃破および拠点の新規占領で得た目標スコアに到達する |

## 実装仕様

### アーキテクチャ

```
src/
├── game/                    # UIから独立したゲームロジック
│   ├── types.ts             # 状態、地形、ユニット、座標の型
│   ├── state.ts             # 盤面・ゲーム状態の生成と参照
│   ├── commands.ts          # 移動、攻撃、占領、生産、乗船、上陸、ターン終了
│   ├── units.ts             # 9種のユニット能力・分類
│   ├── terrain.ts           # 地形規則、移動コスト、経路探索
│   ├── facilities.ts        # 拠点判定と工場／港湾の生産規則
│   ├── combat.ts            # ダメージ計算と戦闘予測
│   ├── fog.ts               # 視界・敵ユニットの可視判定
│   ├── maps.ts              # JSON互換のシナリオ定義・検証・組み込みマップ
│   ├── victory.ts           # 勝敗条件、スコア、保持進行度の評価
│   ├── session.ts           # セーブ／ロード、コマンド再現、保存形式の検証
│   ├── replay.ts            # リプレイ作成、検証、シリアライズ
│   ├── campaign.ts          # キャンペーン進行、解放、成績評価、保存
│   ├── editor.ts            # シナリオエディタの状態操作とJSON入出力
│   ├── rng.ts               # 再現可能な疑似乱数生成器
│   └── index.ts             # game モジュールの再エクスポート
├── ai/
│   ├── rules.ts             # 難易度別CPUの生産・輸送・戦闘・移動判断
│   └── index.ts             # AIモジュールの再エクスポート
├── ui/
│   └── boardNavigation.ts   # 盤面のキーボードフォーカス移動
├── main.ts                  # ブラウザUI、入力、セーブ、リプレイ、キャンペーン連携
└── style.css                # 画面スタイル
```

`src/game/index.ts` はゲームを初期化するファイルではなく、ゲームロジックをまとめて再エクスポートする公開窓口です。アプリケーションの初期化とUIの統合は `src/main.ts` が担当します。

### 主要システム

#### ユニット・地形・補給

- ユニットごとにHP、移動力、攻撃力、防御力、射程、燃料、弾薬、視界、生産費を定義しています。
- 地形ごとの移動コストと防御補正を適用します。可変コストの移動範囲はダイクストラ法で求め、残燃料も移動上限に反映します。
- 霧に覆われた敵は視認できず、攻撃やCPUの判断には視認済み情報だけを用います。
- 所有拠点での補給、施設占領、収入、生産を一貫したルールで処理します。

#### 戦闘・AI

- 攻撃前にダメージと反撃の予測を表示します。地形、防御、HP、ユニット種別の相性、射程、弾薬を考慮します。
- CPUは難易度に応じて攻撃リスクと目標優先度を変えます。敵司令部・拠点・確認済み敵を目標に、輸送艦を含む生産と移動を行います。

#### シナリオ・キャンペーン

- シナリオはJSON互換データから検証して読み込みます。不正な組み込みデータには最小限の代替シナリオを用意しています。
- 標準の通常戦に加え、群島・峡谷・包囲戦を含む4ステージのキャンペーンを実装しています。
- キャンペーンでは勝利成績に応じてS/A/B/Cを記録し、次の作戦を段階的に解放します。

#### セッション・リプレイ

- セーブデータとリプレイは、初期状態とコマンド履歴を再現して整合性を検証します。
- JSONの形式・サイズ・ゲーム状態・シナリオID・乗船状態を検査し、壊れたデータや不正なデータを読み込みません。

### 地形一覧

防御側の軽減率は **防御★ × 10% × 現在HP / 100** です。たとえば防御★4の山岳・司令部は、HP100で40%、HP50で20%のダメージを軽減します。

| ID | 表示名 | 防御★ | HP100時の軽減 | 主な役割 |
| --- | --- | ---: | ---: | --- |
| `plain` | 平原 | 1 | 10% | 基本の陸地 |
| `forest` | 森林 | 2 | 20% | 防御補正が高く、一部地上部隊の移動コストが増加 |
| `road` | 道路 | 0 | 0% | 防御補正がなく、地上部隊の移動しやすい地形 |
| `mountain` | 山岳 | 4 | 40% | 防御補正が高く、移動制約が大きい地形 |
| `sea` | 海 | 0 | 0% | 海上部隊が行動する水域 |
| `city` | 都市 | 3 | 30% | 占領できる拠点。収入と補給を提供 |
| `factory` | 工場 | 3 | 30% | 占領できる拠点。収入・補給に加えて陸上／航空部隊を生産 |
| `port` | 港湾 | 3 | 30% | 占領できる拠点。収入・補給に加えて海上部隊を生産 |
| `capital` | 司令部 | 4 | 40% | 占領できる拠点。収入・補給を提供し、司令部占領条件の対象になる |

### ユニット一覧

| ID | 表示名 | 主な役割 |
| --- | --- | --- |
| `infantry` | 歩兵 | 拠点を占領できる基本部隊。輸送艦に搭載可能 |
| `recon` | 偵察車 | 高い機動力と視界を持つ偵察部隊 |
| `tank` | 戦車 | 近接戦闘を担う装甲部隊 |
| `artillery` | 砲兵 | 2〜3マスの間接射撃を行う地上部隊。移動したターンは射撃不可 |
| `rocket` | 自走砲 | 3〜5マスの長射程攻撃を行う地上部隊。移動したターンは射撃不可 |
| `antiAir` | 対空車両 | 低速・短射程だが航空部隊に特化した地上部隊 |
| `fighter` | 戦闘機 | 航空戦に強い航空部隊 |
| `bomber` | 爆撃機 | 地上・海上目標への攻撃に強い航空部隊 |
| `destroyer` | 駆逐艦 | 海上戦を担う艦船 |
| `landingShip` | 輸送艦 | 歩兵1部隊を搭載して海を越える艦船 |

## セットアップ

### 前提条件

- Node.js 22 以上
- npm 10 以上

### インストール

```bash
# リポジトリをクローン
git clone https://github.com/sj55576/MiniStr.git
cd MiniStr

# 依存関係をインストール
npm install
```

### 開発

```bash
# 開発サーバーを起動（http://localhost:5173）
npm run dev

# テストを実行
npm test

# テストを監視モードで実行
npm run test:watch

# 本番ビルド
npm run build

# ビルド結果をプレビュー
npm run preview
```

### デプロイ

`main` ブランチへの push で GitHub Pages に自動デプロイされます。
